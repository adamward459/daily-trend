Your stack — React, React Native, Node, MongoDB

Next.js September 2026 security release: 7 CVEs, patch now

The high-severity one is an SSRF in Image Optimization (CVE-2026-94483) — reachable only if you configure images.remotePatterns, but then an allow-listed remote URL can be pointed at private IP ranges. Four medium issues are cache poisoning and cross-user content leaks in SSG/ISR and 'use cache', and these hit self-hosted apps specifically: Vercel deployments are not affected by the Pages Router one. There is also a low-severity hole in the next dev MCP endpoint that lets any website you visit read your project path, source snippets and route inventory.

Fix: npm install next@16.3.8 (Active LTS) or next@15.5.27 (Maintenance LTS).

Next.js blog

Callstack released Apex, an agentic coding model specialised in React

Callstack — React Native core contributors — trained a model on the RN ecosystem: docs, source, public APIs and real repository conversations. They claim frontier-level results on React Native evaluations across navigation, animations, async state and lists. In a recorded code review on the Expensify repo, Apex finished in 2m16s for $0.09 where Claude Opus 5.5 took 13m30s for $0.60.

Pricing is $0.50 per million input, $0.20 cached, $3.00 output — well under the general-purpose frontier models. Access is via the API at apex.callstack.com, with npx @callstack/apex init for setup, Vercel AI Gateway coming, and self-hosting available. Worth a side-by-side on your own RN code before trusting the benchmark; a narrow model that is 6× faster and 85% cheaper on routine review and test-writing is a real change to how you'd budget agent work.

Callstack blog

Shopify dropped React Native for Swift and Kotlin

Shopify rewrote the Shop app in native code in 12 weeks, and the Shopify app migration is underway. The stated reason is not that React Native failed — they were hitting sub-500ms P75 screen loads and >99.9% crash-free sessions. It is that AI agents removed the cost that justified cross-platform: Head of Mobile Mustafa Ali says agents "can now do enough of the implementation, translation, testing, and review work that it's no longer the deciding factor."

Read this as an economics argument, not a technical verdict on RN. It only holds at Shopify's scale, with two platform teams' worth of native expertise to supervise the agents. For a smaller team, one codebase is still one codebase. But the argument will come up in planning discussions, so it is worth knowing the actual numbers behind it.

Pragmatic Engineer

MongoDB 9.0 goes GA, plus Atlas Agent Engine and Atlas Infinite in preview

MongoDB 9.0 brings up to 35% faster find queries and 30% faster updates, and extends Queryable Encryption to prefix, suffix and substring search on encrypted fields. Atlas Agent Engine (public preview) is a managed agent runtime with four memory types — semantic, episodic, taxonomic, procedural — and least-privilege auth, model- and framework-agnostic, using Voyage AI for retrieval. Atlas Infinite separates compute from storage and claims 189% more performance per dollar on I/O-heavy workloads.

The Agent Engine piece is the interesting one if you are hand-rolling agent memory on top of Mongoose today. It is in preview and available to all Atlas customers without a new contract, so it is cheap to evaluate against your own schema before committing.

LLM app development

Small "decision models" became a real category this week

Two releases in the same week point at the same idea: stop using a chat model for classification. Cloudflare open-sourced Clef and Clef-flash on Hugging Face under Apache 2.0 — typed outputs with probabilities instead of free text, 38.8ms median latency for flash and 209.3ms for the larger one, a 64k context, and a vision encoder. They are served through Workers AI over REST and are Jev-API compatible. Separately, Jeff is a 0.8B open model (MIT code, Apache 2.0 weights) doing one forward pass per decision with a fitted temperature for calibration: 22ms on an RTX PRO 6000, 28ms on an M4 Max, and ~41MB LoRA adapters you can train for a specific task in half an hour to four hours on one GPU.

The practical pattern is routing: Jeff's authors report it handling 87.7% of decisions alone with a 27B fallback, 38× faster overall. If your Express routes call an LLM for triage, intent detection or moderation, this is the week's most directly applicable idea — those calls are classification, and you are paying generation prices and generation latency for them.

Cloudflare blog

Earendil reversed its position on MCP and shipped "Codemode"

Earendil, who had publicly opposed MCP, now support it in Pi 1.0 (MIT licensed). Their diagnosis of what is still wrong is the useful part: most MCP servers dump tools and return text optimised for token count, which composes badly. They argue MCP should sit closer to OpenAPI — structured returns, and tool discovery driven by documentation. Codemode is their answer: a JavaScript sandbox in the trusted harness that orchestrates tool calls statefully, so an agent can combine several tool outputs without spending context on the intermediate results.

If you are building agents on MCP, the composition problem described here is one you will hit. Pi 1.0 also ships deferred tool loading and Anthropic cache optimisation, both worth reading as implementation patterns regardless of whether you use the harness.

Earendil

Simon Willison: we need default hard budget caps on everything

The argument is that coding agents have removed the friction from deploying things that can run up a bill, so a warning email is no longer an adequate guardrail — services should hard-pause on budget exhaustion, with unlimited spend as a deliberate opt-in. He notes AWS shipped spending limits in September 2026 and Google Cloud added Spend Caps in July.

Concrete takeaway for anyone running LLM calls from a Node backend: set the provider-side spend cap today, not the alert. An agent loop that retries on a malformed response will find the bug you did not test for.

simonwillison.net

livenerf: an actual methodology for testing whether a model got worse

922 points on HN for a benchmark that tries to settle the "has it been nerfed" question properly. It calibrates to 78 items (from 2,336 candidates across GPQA Diamond, MMLU-Pro and competition maths) where Opus 5.5 scores 50–70%, runs the same panel against its own baseline daily, and uses a control arm on Opus 5 so that infrastructure changes can be distinguished from model changes. It pre-registers its statistics and requires 99% CIs across two consecutive 10-day windows before declaring a change.

No verdict yet — 6 of 30 baseline days were in at time of writing. Useful anyway: the author found that reduced effort shows up in token counts before it shows up in accuracy, which is a cheap signal you can log yourself if you depend on consistent model behaviour in production.

OpenAI's Dots, and DeepSeek's open-source agent desktop

Dots are always-on agents on GPT-6 Astra, each with its own cloud computer, connecting to 4,000+ apps and doing read-only background research; one is included with Pro and Business Premium. It is a consumer/workplace product — no developer API documented — but it sets the expectation your users will bring to your app. On the other side, DeepSeek Harness Desktop is a free, MIT-licensed agent platform for macOS and Windows with an "everything is a plugin" architecture and a web UI via npx @deepseek-ai/dsh web — a readable open codebase if you want to see how a production agent harness handles execution traces and tool-call debugging.

AI models & research

The $2/$10 mid-tier: Gemini 4 Argon, GPT-6.1 Sol and Sonnet 5.5 all landed in one week

All three arrived within seven days at the same headline price of $2 per million input and $10 per million output. GPT-6.1 Sol matches Astra on DeepSWE v1.1 at a fifth of Astra's price, beats the previous Sol by 6.4 points on it, scores 7 points higher on OSWorld 2.0, and cuts factuality errors ~32% at low reasoning effort; cached input is $0.10. Claude Sonnet 5.5 (Sept 28) runs 30%+ faster than Sonnet 5, jumps to 70.6% on Terminal-Bench 4.0 from 10.3%, nearly matches Opus 5.5 on GDPval-AA, and costs up to 30% less per task by using fewer output tokens. Gemini 4 Argon is the outlier: 77.9% on DeepSWE v1.1, a 1M-token output limit (up from 64K), 95% cached-input discount, and a security focus — 68% on CWE-bench v1, autonomously finding and patching vulnerabilities — but it is gated behind the Fairwind program plus paid API and AI Ultra.

For your purposes the pattern matters more than the individual scores: a model good enough for most coding and agent work now costs $2/$10, and per-task cost is falling faster than per-token price because these models spend fewer output tokens. If you picked a model tier six months ago, the arithmetic has changed.

OpenAI / Anthropic / Google

Kolibri: a 78B MoE under Apache 2.0, with 3.46B active per token

Aleph Alpha released Kolibri on October 3 — 78.1B total parameters, 6 of 384 experts active per token across 50 layers, a native 262,144-token context tested to ~1M, and Apache 2.0. German and English only, with a UniBPE tokenizer needing 11.2% fewer tokens for German than GPT-5's, sliding-window attention on 40 layers with every fifth layer global, selectable reasoning effort, and abstention training (Merlin-Arthur) so it says it does not know instead of inventing. "Sovereign" here means built and trained in Germany and Finland under European law.

The architecture is the lesson even if you never use it: 3.46B active parameters at 78B quality is the direction self-hostable models are heading.

tej.as

Strata runs a 125B model on a single consumer GPU

An MIT-licensed inference engine that gets Qwen3.8-Flash-Next (125B) onto a gaming PC by splitting the work: hot expert layers on the GPU, the full model in RAM, the remainder on CPU, lookup tables on SSD, plus speculative decoding ("guess and check") for a 1.6–1.8× latency win. Needs 12GB+ VRAM, 32GB RAM (64GB recommended) and ~80GB disk; roughly 94 tok/s at Q2_0 on an RTX 5070. One-click install on Windows and Linux, and it serves OpenAI- and Anthropic-compatible APIs locally.

That last detail is the useful one: you can point an existing SDK client at localhost and test your app against a local model without changing your code.

Pressure on the labs: Newport calls for a Congressional investigation

Cal Newport argues that OpenAI and Anthropic shaped public perception of AI risk and then lobbied for rules favouring their own position, and asks Congress to examine three things: specificity about which systems are actually risky, internal safety procedures, and how the labs' futurist beliefs drive research speed. It landed the same week as an Atlantic piece by a departing OpenAI safety researcher titled "I quit OpenAI because its culture is broken," which drew 790 comments on HN — among the week's most-discussed threads.

"Coding is not solved" — 584 points, 544 comments

Alex Ewerlöf's argument is that "coding is solved" confuses code generation with software engineering, and that the expensive parts — scalability, security, reliability, maintenance — are untouched by cheap generation. His sharpest point: you cannot be accountable for what you do not understand, and only humans can carry that accountability. A useful counterweight to read next to the Shopify item above.

blog.alexewerlof.com

Git 3.0's SHA-256 default is contested

Scott Chacon argues the switch solves a theoretical problem at real ecosystem cost: submodules break across hash formats, every 40-character hash in your docs and chat history becomes obsolete, converting a repo breaks GPG signatures, and hosts would need parallel SHA-1 and SHA-256 mirrors. He proposes independent tree-hash headers in signed commits instead. Worth knowing before you create a repo on Git 3.0 and cannot push it to an existing remote.
